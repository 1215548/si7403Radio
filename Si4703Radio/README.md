# Si4703Radio — ESP32-C3 Supermini FM 收音机

板子：ESP32-C3 Supermini。屏：2.42 寸 OLED，SSD1309，128×64，4 线 SPI。
收音：Si4703（仓库名 `si7403Radio` 里的 `si7403` 是笔误，芯片是 Si4703，
手册在仓库根目录 `Si4703_datasheet.pdf`）。音频从 Si4703 的 LOUT/ROUT
出，接耳机/功放即可，本工程不经过 ESP32。

## 编译上传

板子选 **ESP32C3 Dev Module**，`USB CDC On Boot: Enabled`，
分区选 **Huge APP (3MB No OTA/1MB SPIFFS)**（固件已超默认 1.25MB
分区：GB2312 字库约 240KB + WiFi/HTTPS 约 300KB）：

```bash
arduino-cli compile -j 1 \
  --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc,PartitionScheme=huge_app \
  --build-path ~/workspace/build/si4703radio Si4703Radio
```

上传用同一 FQBN 加 `--port <串口>`。串口监视器 115200，走 USB CDC。

> 注意：从默认分区切到 Huge APP 会改变分区表，首次烧录会清空
> NVS（已保存的 WiFi 密码、预存台需重新配置一次），之后不再影响。

## 分阶段验收

### 阶段 1：OLED、按键、LED（不依赖收音机）

1. 上电：LED 常亮，屏先播 Linux 风开机动画（反白标题
   `SI4703 RADIO OS` + 版本、内核日志逐条出现、底部进度条、
   最后停在 `root@si4703:~#` 闪烁方块光标，约 3 秒）。
2. 按任意键：LED 闪一下，串口打印 `KEY xx state=n`；首页播放时
   顶部状态行切换成按键布局。
3. 串口发 `t`：显示几何测试图（点/线/圆 + `Si4703 FM TEST OK`），1.5 秒后回主界面。

### 阶段 2：Si4703

上电自动：复位选 3-wire → 读 DEVICEID/CHIPID → 配寄存器 → 上电 →
调到 98.0MHz。成功时串口打印：

```
RADIO OK: DEVICEID=0x... CHIPID=0x1253 freq=98.00MHz
```

主界面显示频率 / RSSI / ST（立体声）或 MO（单声道）/ VOL，
LED 常亮表示当前是立体声信号。失败时屏幕显示 `NO RADIO`、
LED 慢闪、串口打印原因和寄存器值，按键/屏幕照常工作，串口发 `r` 重试。

## 操作

### 首页三态

- **收音播放**（收音机 OK 且未静音）：顶部状态行有两种布局——
  空闲（5 秒无按键）显示 `RSSI46 11/17 14:03:22 Sun`（RSSI、日期、
  带秒时间、英文星期，最长 25 字符刚好一行）；按下调频/音量后的
  5 秒内显示 `RSSI46 ST V10 3/12 14:03`（RSSI、立体声、音量、
  频道序号/总数、不带秒时间）。大字体频率；中行显示台名（有 RDS
  时用 PS）或瞬时消息；底部 16 柱频谱律动，约 20fps。
  顶部行、频率区、中行、底部频谱全部按页局部刷新，正常运行时
  （包括带秒时钟每秒变化）不整屏重画。
- **时钟**（不播放且 NTP 已同步）：大时间 + 日期 + 星期 + 农历
  （如 `丙午马年十月初八`）；KEY3/KEY4 切换两种显示风格。
- **预留**（不播放且无时间）：显示 `功能预留`，等后续功能。

### 按键

首页：KEY5 进菜单；播放时 KEY4/KEY3 切台（有预存台时在预存台间
切换，无预存时 ±0.1MHz 调频）、KEY2/KEY1 音量±；不播放且时间
有效时 KEY4/KEY3 切换时钟风格，其余情况 KEY1~KEY4 暂不响应。
每次检测到按键：LED 闪一下、串口打印 `KEY xx state=n`，顶部状态行
立即切到按键布局（即使音量/频率已在边界，也有可见反馈）。

菜单内统一：KEY3 上、KEY4 下、KEY5 确认/执行、KEY1 返回。

- **菜单**：WiFi配置 / 收音机设置 / 任务状态 / 日期时间 /
  关于版本 / 字体切换 / 返回首页。菜单文字用 12px 紧凑字（汉字由
  16 点阵降采样），一屏 4 项；“字体”项显示当前字体（`字体: 思源`
  或 `字体: 等线`），KEY5 立即切换整套中文界面并保存；每项带小
  图标，选中行反白，右侧竖滚动条
  显示当前位置；上下键首尾循环时可见窗口会自动跟随，不会出现
  “有光标但看不到选中项”。标题栏右侧显示时间（已联网时），
  后台播放时显示 `FM98.0 12:34`（频率+时间）。各信息页同为
  12px、一屏 4 行，日期时间/农历不再被截断。
- **WiFi配置**：KEY5 只切换网页配置服务的开/关（标题栏右侧
  `AP ON/AP OFF`）。已连上路由器时，页面固定显示当前连接的
  WiFi 名和 IP：第一屏为 状态 / WiFi 名 / IP / 信号，向下滚动
  可看 网页服务 / AP 地址。开服务后手机/电脑连 AP `Si4703Radio`
  （开放无密码），浏览器打开 `192.168.4.1`，网页上填路由器
  WiFi 名称、密码和 API Key（预留字段，仅保存），点保存后设备
  自动连接该 WiFi，约 10 秒后刷新页面看状态。连上 WiFi 后自动
  NTP 校时（阿里云/pool），再自动拉当天农历；日期时间页和时钟
  首页随之显示。AP 启动时不做阻塞式 WiFi 扫描（扫描会占用射频、
  打断 AP，导致手机搜不到热点），SSID 由网页输入框手输。
- **收音机设置**：自动搜台 / 手动调频+ / 手动调频- /
  音量调整+ / 音量调整- / 后台播放（开/关）/ 返回菜单。
  自动搜台从 87.5MHz 起全波段扫一遍（最多 40 个台，最长 120 秒，
  按 KEY1 取消），搜完回到首页、停在第 1 个台并出声；预存台存
  NVS，上电恢复、开机即调到第 1 个预存台。
  后台播放“开”：进菜单保持出声；“关”：进菜单自动静音，回首页
  恢复。返回菜单那一项：静音并返回菜单（不恢复）。
- **任务状态**：FreeRTOS 各任务名、状态（R 运行/r 就绪/B 阻塞/
  S 挂起/D 已删）、栈余量、优先级，第一行是空闲堆和任务总数。
- **日期时间**：NTP 时间、日历、星期、农历（干支+生肖+月日）；
  未联网时显示“时间未同步”。
- **关于版本**：固件版本（`pins.h` 的 `FW_VERSION`）、编译日期时间。

串口（115200）：`f 98.5` 调频 / `s` 向上搜台 / `S` 向下搜台 /
`v 12` 音量 0–15 / `m` 静音开关 / `i` 读全部寄存器 00h–0Fh +
预存台 + WiFi 状态 / `t` 测试图 / `r` 重启收音机 /
`w` 开关 WiFi 配置热点 / `p` 列预存台 / `?` 帮助。

## 设计要点（都是手册里的依据）

- **Si4703 用 3-wire，不用 I2C。**引脚表把 SDIO/SCLK 与 OLED 的
  MOSI/SCLK 共用、SEN 当 CS_1，这正是 3-wire 接法（手册 §4.8.1）；
  2-wire 需要 SCLK/SDIO 上拉且 SEN 复位时为高，引脚表里没有。
  3-wire 控制字 9 位：`0110 + R/W + 寄存器地址`，后跟 16 位数据；
  读时半周期转向后由芯片在 SCLK 上升沿送出、控制器在下降沿采样。
- **总线模式选择（手册 §4.9 方法 1）。**GPIO3 悬空，片内 1M 下拉
  使其为 0；RST 上升沿采样 SEN=0、SDIO=0 即选 3-wire。复位时
  SCLK 全程保持低（上升沿前 300ns 内不能有上升沿），RST 低电平
  保持 1ms（GPIO3 放电需 ≥100us）。
- **晶振（手册 §4.7、寄存器 07h）。**模块板载 32.768kHz 晶振时，
  须在 ENABLE=1 之前置 XOSCEN 位（`SI4703_USE_XTAL`，见 `pins.h`）。
  若模块既无晶振、RCLK 又没接外部时钟，调谐/搜台必然失败。
  上电前 TEST1 的 bits13:0 保持 0x0100，上电后为 0x3C04。
- **上电验证（手册 §6）。**上电前 CHIPID 应为 0x1200，上电后为
  0x1253；DEVICEID 低 12 位 MFGID=0x242。任一不对即报具体值，
  不猜原因。
- **芯片可能是 Si4702，不是 Si4703——但别只看上电前的 CHIPID。**
  市售“Si4703”模块有上电前报 CHIPID=0x0800 的（DEV=0，看着像
  Si4702），可上电后同一颗芯片报 0x0A50（DEV=9、FW=0x10），
  实为老固件的 Si4703（2026-11-16 实测）。驱动按 DEV 位段区分
  两种芯片、不再卡死 0x1200/0x1253；上电成败改看上电后 DEV=1/9
  且 FIRMWARE 非零。调频、搜台、音量两者完全相同，差别只有 RDS。
- **中国 FM 参数。**波段 87.5–108MHz，步进 100kHz，
  去加重 50us（SYSCONFIG1 的 DE=1），SEEKTH=0x19。
- **seek/tune 期间少碰 SDIO（手册 4.7.1 勘误）。**内部晶振会被
  SDIO 活动干扰致误调；本驱动先静默 100–150ms 再稀疏轮询 STC。
- **OLED 与收音机共用 SPI 引脚。**OLED 用硬件 SPI，收音机用
  GPIO 位-bang；每次收音机传输前 `SPI.end()` 借走引脚，结束后
  `SPI.begin()` 还给 OLED；单线程顺序调用，不打架。
  OLED 写-only SPI 无法回读，初始化成功不等于屏亮，屏不亮先查
  供电/复位/接线。

- **汉字字库是全 GB2312，不是只含界面用字。**`gb2312_font.h`
  共 7445 字（汉字 6763 + 符号 682），16x16 点阵，每字 32 字节，
  由 Noto Sans CJK SC 在 16px 下渲染、阈值二值化生成（生成脚本
  在本机，不在仓库内）；运行时按 Unicode 二分查找字形。
  另加 `gb2312_font_deng.h`：同样是 7445 字 16x16，由 Windows
  等线 Deng.ttf 16px 渲染（阈值 32），索引与 Noto 完全一致，只有
  字形表不同。两套各占 Flash 约 240KB；主界面 16px、菜单 12px
  （运行时 2x2 降采样）都跟随当前字体。菜单“字体: 思源/等线”
  一键切换，选择存 NVS `ui/font`，下次上电恢复。
  注意：等线是微软字体，仅供本机自用；把点阵嵌入后对外分发
  固件前请确认字体授权。
  混排绘制：中文 16 点阵 + ASCII Font16（同高 16px），见
  `cn_font.cpp`；查无此字画空心框占位，不静默丢字。
- **农历拉取必须放独立任务。**TLS 握手要吃掉数 KB 栈，在 loop
  任务（默认栈 8KB）里直接跑 `WiFiClientSecure` 易栈溢出重启，
  且 DNS/TLS 阻塞时主循环停摆会触发看门狗复位（S2 工程同款教训）。
  本工程农历用独立 12KB 任务（`wifi_portal.cpp`），loop 只发通知、
  取结果。接口 `https://api.530.news/api/lunar`（公开万年历，
  无密钥），`setInsecure` 跳过 CA 校验；只取干支、生肖、农历月日
  四个字段，失败保留旧值、60 秒后重试。
- **WiFi 连接全程非阻塞。**上电 `WiFi.begin()` 后在 `tick()` 里
  看状态，连上才启动 NTP；网页保存密码后同样后台重连，不卡主循环。
  网页服务开关只控制 AP + WebServer，STA 连接不受影响。
- **预存台与切台。**自动搜台用 `seek up` 逐跳找台，绕回起点即停
  （靠“找到的频率 ≤ 第一个台”判定），每跳之间刷新进度、响应
  KEY1 取消；单跳最慢 12 秒（空频谱），整圈最长 120 秒。首页切台
  走预存表，手动调频/串口调频后预存序号清零（当前频率不再是预存台）。

- **防频闪（2026-11-16，v0.3.1 定版）。**原来每秒全屏重发
  一次：底层每字节一个 SPI 事务（1024 次、数毫秒逐页滚动更
  新），每秒一次肉眼可见。分三层修：
  ① `flush()` 先算 1024 字节显存的 FNV-1a 哈希，内容完全没
  变就不调驱动，静止画面零 SPI 流量；
  ② 变了则全屏重发，但每页 128 字节一次突发事务（`SPI.
  writeBytes`），全屏约 1ms；
  ③ **RSSI 迟滞**：真实 RSSI 每秒 ±1~3 抖动，直接画会让信
  号条/数字每秒都变、每秒触发一次重发——这是 1 秒一闪的触
  发器；迟滞后只有变化 ≥3 才更新显示值。
  教训：局部刷新（只发变化的页）曾因初始化是横向寻址、0xB0
  页地址命令被忽略而错页（信号条在多个纵向位置重复），已删
  掉改回全屏重发——全屏按顺序流写在页/横向两种寻址模式下都
  对，不依赖寻址模式。初始化仍保留 0x20/0x02 页寻址。
- **开机自动搜台（2026-11-16）。**`setup()` 后 `bootScan()`：
  收音机正常且 NVS 里无预存台时自动跑一次全波段搜台（进度屏，
  KEY1 取消，扫完回首页出声）；有预存台时直接调到第 1 台，不重
  扫。首次烧录 huge_app 会清 NVS，不扫就停在 98.0MHz 无台可听。
- **RSSI 直接显示数字 + 底部频谱律动（2026-11-16，v0.3.3）。**
  首页信号行取消进度条，改显示 `RSSI 46` 数字（仍用迟滞值）。
  底部原 RT 行（`FM 87.5-108MHz 100kHz` 在屏底被截断）取消，
  改为 16 根伪频谱柱子（y=52..63，6px 宽、间隔 2px，底部对齐，
  每根带 1px 峰值保持标记）。Si4703 不输出音频电平，所以是装饰
  性律动：高度由正弦波（时间+相位）+ RSSI 包络决定，信号越强整
  体越高，约 8fps。频谱只重画底部区域并局部刷新第 6/7 页
  （`OLED_2IN42_RefreshPages`，每次先强制页寻址模式再逐页定
  址突发写，与全屏重发同寻址/顺序，不会再错页）；瞬时消息
  （VOL/FOUND 等）激活时暂时代替频谱显示在同一区域，过期后恢
  复。RT 滚动的 600ms 强制重画已随 RT 行一起去掉。
- **频谱不动 + 切台消息占底部（2026-11-16，v0.3.4）。**
  v0.3.3 的柱子几乎不动：宿主仿真证实柱高只在 5..8 之间变
  （3px，太 subtle），改为基线更低、摆幅更大、速度更快
  （中间柱子 3..12，9px，周期约 1.8s，仿真确认波峰在各柱间
  移动）。布局按用户要求重排：RSSI/ST/VOL/台序号 + 时间放
  顶行（Font8）；切台消息 `CH 3/4 103.00`、VOL、FOUND 等改
  走 y=42 中行（无消息时显示台名），不再占用底部；底部频
  谱一直显示、不被消息打断；消息过期后 tick() 清掉并重画
  中行（恢复台名）。
- **柱子还是不动（2026-11-16，v0.3.5）。**
  v0.3.4 的大摆幅在实机上仍不动，说明不是摆幅问题，是局部
  刷新（refreshPages）这条路本身不生效：疑似页寻址模式未生
  效，0xB0 页命令被忽略、数据写到错的位置；且它还会更新
  _lastHash，让全屏 flush 误判显示已同步而跳过发送。
  改走全屏重画：tickSpectrum 每 120ms 更新柱高并置 _dirty，
  由 drawCurrent 全屏重发（全屏重画是已验证的可靠路径，切台
  消息更新即走此路；突发写约 1ms，8fps 下不会闪）。柱子改

## 注意 / 已知风险

- **IO9（LED）是 BOOT Strapping 脚，复位时必须为高。**LED 原接法
  （IO9→电阻→LED→GND）在复位时把 IO9 拉低，板子每次上电都进下载
  模式、程序不跑（2026-11-16 实测）。改法：LED 改低电平有效——
  正极经电阻接 3V3，负极接 IO9；代码 `pins.h` 里
  `LED_ACTIVE_LOW=1` 已跟随此接法，`Led` 类内部翻转电平，
  主程序不用改。顺序：先改线，再烧新程序。
  只加下拉电阻不可靠：芯片内部上拉约 45kΩ，LED 支路到地会把它
  拉到 2.48V（VIH 阈值）以下；若坚持高电平亮，IO9 后加 NPN 管
  （IO9→10k→基极，发射极接地，集电极→LED 负极，LED 正极经电阻
  接 3V3），并把 `LED_ACTIVE_LOW` 改回 0。Supermini 引出的
  13 个 GPIO 全被占用，LED 没有空闲脚可换。
- **IO8（KEY5）和 IO2（Si4703 RST）也是 Strapping 脚。**
  上电/复位时不要按住按键；RST 由程序控制，复位后即拉高。
- **KEY3/KEY4 在 IO20/IO21**，那是 UART0 的 RX/TX；本工程串口
  走 USB CDC，不占 UART0，所以可以做按键。不要再启用 Serial0。
- **RDS 已接（2026-11-16，`rds_parser` 模块）。**SYSCONFIG1
  RDS=1 且 POWERCFG RDSM=1（详细模式，才有 RDSS 同步标志和各块
  BLER 误码等级）；主循环每 50ms 收组，BLER>1 的块丢弃。
  屏幕显示：PS 台名 + 节目类型（第 2 行）、RadioText 滚动
  （第 3 行，超 21 字符时每 600ms 滚一格）、CT 时间（无文本时
  显示在第 3 行）；串口在内容变化时打印 `RDS PI=… PS="…" RT="…" CT=…`。
  换台/搜台成功后旧台内容自动清空，PI 变了也一样。
  限制：RDS 要信号够好才能同步（RSSI 十几的弱台收不到）；
  国内多数 FM 台不发 RDS，莆田本地台大概率没有——屏幕长期
  显示 RSSI 行、串口报 `RDS no sync` 就是台端没发，不是代码问题；
  RDS 字符集是拉丁文，中文台名发不出来，个别台用 GB 编码塞
  RadioText 会显示乱码。Si4702 没有 RDS，`pollRds()` 直接跳过。
- **重新上电收不到台、下载后重跑却正常（2026-11-16）：是
  32.768kHz 晶振冷启动太慢，不是 C3 卡在复位。**手册初始化
  流程（§4.11 图 9）要求先提供 RCLK 再置 ENABLE；冷启动晶振
  从零起振要数百毫秒~1 秒以上，原来 XOSCEN 置位后几毫秒就
  上电，时钟还没稳就上电/调谐，必然失败。下载后重跑时模块
  一直带电、晶振没停过（1ms 的 RST 脉冲停不掉高 Q 晶振），
  所以没事。修复：XOSCEN 置位后等 1 秒再上电，调谐失败再等
  500ms 自动重调一次。注意：这与 C3 本身无关——C3 若卡在复
  位/下载模式，屏幕根本不会亮，`NO RADIO` 这几个字都显示不出来。
